<xo-view>

@xoong/data import '@xoong/data/view';

Declare a screen: get names the GET operation to read. Children are bound to the result. Add live to apply server-sent updates.

Attributes

AttributeTypeDefaultWhat it does
getoperationoperation—A path ("/users") or operationId.
liveflagflagoffApply live updates from the event stream.
url-paramslistlist—Comma-separated param names kept in the page URL (shareable, survive reload and Back): status,q,sort,offset.
p-<name>texttext—The value of the path parameter "name" of the <xo-view get> operation (p-id="42"; p-id="?id" reads ?id= from the page URL; p-id=":id" reads a route parameter).

Events

  • xo-done An action succeeded.
  • xo-error A load or an action failed.
  • xo-invalid A form was not sent because it is invalid.
  • xo-notice A message for the toast.
  • xo-go An action asked to go to another page.

Example

<xo-view get="listPeople" url-params="name,role">
  <p xo-if="$loading">Loading…</p>
  <p xo-if="$error">{$error.detail}</p>
  <ul>
    <li xo-each="items">{name} · {email}</li>
  </ul>
</xo-view>

<xo-router>

@xoong/ui import '@xoong/ui';

A History-API router declared in markup: one <template xo-route> per route, optional <template xo-layout> shells. Links are intercepted, aria-current marks the active one. Guards and leave-vetoes are JavaScript (router.guard, router.beforeNavigate).

Attributes

AttributeTypeDefaultWhat it does
basetexttext—Path prefix the app lives under, for example /admin.
base-linksflagflagoffA root-relative link such as /users inside the router means /admin/users, so the same screens mount under any base. rel="external" leaves the app.

Events

  • xo-navigate The router moved to another location.
  • xo-error A load or an action failed.

Example

<xo-router base="/admin" base-links>
  <template xo-layout="shell">
    <nav><a href="/users">Users</a></nav>
    <main xo-outlet></main>
  </template>
  <template xo-route="/users/:id" layout="shell" title="User">
    <xo-view get="getPerson" p-id=":id"><h1>{name}</h1></xo-view>
  </template>
  <template xo-route="*">Not found</template>
</xo-router>

$loading, $refreshing

$loading is true while a request runs and there is nothing to show yet. $refreshing is true while a request runs and the previous result is still on screen (a sort or a page loads), so the view does not collapse. The view also carries data-refreshing for CSS.

Example

<xo-view get="listPeople">
  <p xo-if="$loading">Loading…</p>
  <p xo-if="$refreshing">Updating…</p>
</xo-view>
