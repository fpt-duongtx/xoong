How it works

xoong has three layers, and you can stop at any of them: a reactive core and base element, a data layer generated from OpenAPI, and ready-made admin parts on top.

Data

xoong sync turns your OpenAPI document into operations.json. A <xo-view get="listPeople"> calls the operation, caches the answer in a shared store (records with the same id are shared between screens) and exposes $loading, $error and the data to the markup inside it. You never write a cache key, an HTTP client or an error handler.

<xo-view get="listPeople">
  <p xo-if="$loading">Loading…</p>
  <p xo-if="$error" role="alert">{$error.code}: {$error.detail}</p>
  <ul>
    <li xo-each="items">{name} <small>{email}</small></li>
  </ul>
</xo-view>
npx xoong sync openapi.json

Actions and forms

Writes are attributes too. A button runs an operation; after it succeeds, every cached query whose path overlaps it is refetched, so lists stay current without extra code. A form with <xo-form op="createPerson"> is drawn from the request schema: nested objects, arrays and unions included. Validation comes from the same schema, with your own rules by path.

<button xo-click="POST /api/people/{id}/disable" xo-confirm="Disable {name}?" xo-notice="Disabled">Disable</button>

<xo-form op="createPerson" submit="Add person"></xo-form>
// Only when HTML is not enough: the same client, typed from api.d.ts
import { getClient } from '@xoong/data';

const created = await getClient().mutate('createPerson', {}, { name: 'Ada', email: 'ada@example.org' });

Pages

<xo-router> is a declarative History-API router with nested layouts, guards and a "leave this page?" question for unsaved forms. Public pages stay one HTML file each and can be prerendered with @xoong/ssr.

<xo-router base="/admin">
  <template xo-layout="shell">
    <nav><a href="/people">People</a></nav>
    <main xo-outlet></main>
  </template>
  <template xo-route="/people/:id" layout="shell" title="Person">
    <xo-view get="getPerson" p-id=":id">...</xo-view>
  </template>
  <template xo-route="*">Not found</template>
</xo-router>

Language

@xoong/i18n uses plain JSON catalogs and ICU-style messages. xo-t translates markup, and every built-in string (table, forms, controls) is a catalog key, Vietnamese included.

<h1 xo-t="home.title">Welcome</h1>
<input xo-t="placeholder:search.placeholder" placeholder="Search">
import { configureI18n, setLocale } from '@xoong/i18n';

configureI18n({ locale: 'en', load: (locale) => fetch(`/i18n/${locale}.json`).then((r) => r.json()) });
await setLocale('vi');

Safety

xoong build rewrites imports to files and removes the need for inline code, so the output runs under default-src 'none'; script-src 'self'; style-src 'self'. This site is built that way, and its tests fail on any CSP violation. Interpolated text is escaped, javascript: URLs become about:blank, and rich text is sanitised on every input.
