How it works

Data

xoong sync turns your OpenAPI document into operations.json. A <xo-view get="listPeople"> calls the operation, caches the answer in a shared store (entities with the same id are shared between screens) and exposes $loading, $error and the data to the markup inside it.

Actions and forms

Buttons use xo-click="POST /users/{id}/disable". A form with <xo-form op="createUser"> is drawn from the request schema: nested objects, arrays and unions included. Validation comes from the same schema, with your own rules by path.

Pages

<xo-router> is a declarative History-API router with nested layouts, guards and a leave question for unsaved forms. Public pages can be prerendered with @xoong/ssr.

Language

@xoong/i18n uses plain JSON catalogs and ICU-style messages; xo-t translates markup.

Safety

xoong build rewrites imports to files and removes the need for inline code, so the output runs under default-src 'none'; script-src 'self'.

xoong is a working prototype (0.0.x). MIT licence.
