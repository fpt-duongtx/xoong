Controls

The controls every admin needs, as custom elements in the Light DOM with plain CSS. @xoong/controls depends only on @xoong/core, so it works with or without the rest.

import '@xoong/controls';   // registers every element; or import one: '@xoong/controls/tabs'
<link rel="stylesheet" href="/@xoong/controls/controls.css">  <!-- optional; one @layer, uses the --xo-* tokens -->

Tabs

The WAI-ARIA tabs pattern with automatic activation: Left and Right (wrapping), Home and End move and select, and only the selected tab is in the tab order. xo-tab is the label; the section's id is its key. Panels are hidden, not removed, so their form fields stay in the form. The code tabs on this page are made with it.

Menu and tooltip

The menu button pattern: click, Enter, Space or ArrowDown opens it (ArrowUp opens on the last item); arrows wrap, Home and End jump, a letter jumps to the next item that starts with it, Escape closes and returns to the trigger. The list is drawn in the top layer with the Popover API, so a table cell or a scroll area never clips it, and it is positioned through the CSS object model, which a strict CSP allows. A tooltip shows after a delay on hover and at once on keyboard focus, stays while the pointer is on it (WCAG 1.4.13) and describes, never names: an icon-only button still needs aria-label.

Combobox and tags

Both are form controls: name, required, disabled, value, validity, dirty and touched, and they work in <form xo-submit> like a native field. The value is a string, or an array with multiple and for tags. Options come from <option> children, from el.options, or from the schema's enum. creatable lets people add a value that is not in the list; remote leaves filtering to you through the xo-search event.

Keys: ArrowDown and ArrowUp open and move (the focus stays in the input, aria-activedescendant follows), Enter picks, Escape closes, Backspace on an empty field removes the last chip. In tags, Enter or a comma adds the typed text. Enter never submits the form while the list is open.

In a generated form

<xo-form> draws a control for any field with a widget hint that is a tag name: xo-combobox, xo-tags, xo-richtext, or your own element built on XoControl.

{
  "fields": {
    "Page.topics": { "widget": "xo-combobox" },
    "Page.keywords": { "widget": "xo-tags" },
    "Page.role": { "widget": "xo-combobox" }
  }
}
"keywords": { "type": "array", "items": { "type": "string" }, "x-xoong-widget": "xo-tags" }

Build your own control

A control that takes part in forms extends XoControl. It gets a value, validity, dirty, touched, name and disabled, and talks to the form binder through ElementInternals. You only write the rendering and call userInput() when the person changes something.

import { XoControl, define, html } from '@xoong/core';

class RatingStars extends XoControl {
  render() {
    return html`${[1, 2, 3, 4, 5].map((n) => html`
      <button type="button" aria-pressed=${() => String(this.value >= n)} @click=${() => this.userInput(n)}>★</button>`)}`;
  }
}
define('rating-stars', RatingStars);
<form xo-submit="updateReview">
  <rating-stars name="rating"></rating-stars>
  <button>Save</button>
</form>
