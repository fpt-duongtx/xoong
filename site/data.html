Data and tables

Reads are <xo-view get>. Writes are xo-click and xo-submit. The data layer does the caching, retries, loading and errors.

Start-up

This is all the JavaScript most apps need. operations.json is generated by xoong sync; baseUrl is where your API lives.

import { configure } from '@xoong/data';
import '@xoong/data/view';
import '@xoong/ui';
import operations from '/.xoong/operations.json' with { type: 'json' };

configure({ api: operations, baseUrl: '/api' });
npx xoong sync openapi.json

A table in one element

<xo-table> draws a table from the view's data. The attributes below turn on sorting (sort query parameter), a search box per filter (the field's query parameter), row selection, bulk actions and paging (limit, offset and total in the response). Children fill cells: slot="role" replaces the role cell, any other element goes in the last cell.

{role} 
<xo-view get="listPeople">
  <xo-table columns="name,email:E-mail,role" sortable filters="name:Search by name" selectable page-size="5" empty="Nobody here">
    <span slot="role" class="badge">{role}</span>
    <button xo-click="deletePerson" xo-confirm="Delete {name}?" xo-notice="Deleted">Delete</button>
    <button slot="bulk" xo-click="deletePerson" xo-selected>Delete ticked</button>
  </xo-table>
</xo-view>
AttributeWhat it does
columnsfield, field:Label or field:Label:format, comma separated
sortableHeader buttons set sort (name, then -name)
filtersname:Search by name: a search box that sets that query parameter
selectableA checkbox per row; slot="bulk" buttons run once per ticked row
page-sizeSets limit and shows Previous and Next (offset)
emptyThe text shown when there are no rows

Your own markup

When a table is not the right shape, write the markup. xo-each repeats an element for each item, xo-if shows it conditionally, {name} reads a field, and xo-param sets a query parameter and refetches (the button for the current value gets aria-current). Text is always escaped.

Loading…

{$error.code}: {$error.detail}

  • {name} {role}
    {email} 
<xo-view get="listPeople">
  <p class="toolbar">
    <button xo-param="role=">Everyone</button>
    <button xo-param="role=admin">Admins</button>
    <button xo-param="role=editor">Editors</button>
    <button xo-param="role=viewer">Viewers</button>
  </p>
  <p xo-if="$loading" aria-busy="true">Loading…</p>
  <p xo-if="$error" role="alert">{$error.code}: {$error.detail}</p>
  <ul class="people">
    <li xo-each="items">
      <strong>{name}</strong> <span class="badge">{role}</span><br>
      <a href="mailto:{email}">{email}</a>
    </li>
  </ul>
</xo-view>

Loading, empty and error

A view tells you in which state it is: $loading while a request runs, $error when it failed, and an empty list otherwise. <xo-table> shows its empty content only when the list is really empty (not while loading, not after an error); a <template slot="empty"> gives it any markup. xo-refresh on a button fetches the view's data again: a "Try again". Say what happened, what to do, and offer one action.

Try it: type zzz for an empty list, or fail: the first request with it fails, and Try again then succeeds.

Actions

A button with xo-click calls an operation by name (or as METHOD /path). {id} and other path parameters come from the row. After it succeeds, the queries it affects are refetched. These attributes shape the call:

AttributeWhat it does
xo-confirm="Delete {name}?"Asks first, in a native dialog
xo-notice="Saved"Shows a toast on success; errors always show one
xo-with="role=admin"Adds fields to the request body
xo-optimistic="role=admin"Applies the change at once, undone if the call fails
xo-selectedRuns once per ticked row (or sends the ticked ids in one request)

Errors and loading

A running call sets aria-busy on the button. A failure becomes one error type with status, code and detail (from application/problem+json, { error: { code, message } } or { detail }), shown by <xo-toast> or by $error in your markup. Listen for xo-done and xo-error to react in code.

<xo-view get="getPerson" p-id="99">
  <p xo-if="$error" role="alert">{$error.status} {$error.code}: {$error.detail}</p>
</xo-view>
<xo-toast></xo-toast>
document.addEventListener('xo-error', (e) => console.warn(e.detail.code, e.detail.detail));
