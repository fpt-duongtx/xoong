# Performance changes, one opportunity at a time

Each line is one revertable change set. Numbers are from `benchmarks/perf/profile.mjs` (flat screen, create 10,000 rows, same machine, one run each) unless said otherwise; the baseline is `results/profile.json`.

| Rank | Change | Why (evidence) | Effect | Risk |
|---|---|---|---|---|
| 2 (part) | `evalParts` builds the text with a loop instead of `map().join()`; `Effect.run` and `dispose` iterate their dependency set directly instead of copying it to an array first | allocation sampling: `bindNode`, `run` and the text bindings allocate arrays on every (re-)run | allocation 7,403 to 6,966 bytes per row (-6%); creation time unchanged (639 to 643 ms, noise); every update path allocates less per effect run | none: same results; unsubscribing edits the source's set, not the effect's |
| 3 | CSS (cheaper table rules, no transition) | style recalculation is 101 ms against 64 ms for a plain table | **measured and rejected**: with no stylesheet at all style recalculation is still 86 to 95 ms; removing the table's `transition` changes nothing (101 to 105 ms); the `tbody tr:last-child td` rule is worth about 15 ms (2.5%) and is a visible border, so it stays | none (not changed) |
| 8 | Init (element definitions) | 4 definitions take 0.3 ms in all (the docs page: 39 in 1 ms) | **nothing to gain** | none (not changed) |
| 9 | Update paths | one field change: 19 effects, 1 text and 6 attribute writes; a tick: 4 effects | **already fine-grained** after the re-render fixes | none (not changed) |
| 1 (done) | Lazy `router.js` and `dialogs.js` (facades in `router-lazy.js`, `dialogs-lazy.js`; exports unchanged; `xoong build` preloads `router.js` only for a page that has `<xo-router>`; SSR imports `@xoong/ui/router`) | 49% of the JS that loaded never ran | JS loaded on the people screen 244.6 to 218.3 KB raw (-10.7%, about -9 KB gzip); never-run share 49% to 45%; on slow 4G graph ready 875 to 854 ms (-2.5%), first row 1,058 to 1,035 ms (-2.1%); a page with no `<xo-router>` makes no request for router.js (test). The graph is latency-bound (33 requests), so bytes buy little time. The form engine is **not** lazy: it attaches while the view binds (prefill, leave guard, first paint of a prerendered form depend on it). **`@xoong/ui` budget: the test sums all sources, 12.33 KB at the start, 12.75 KB now (the two facades are 0.4 KB); the eager part alone is 7.65 KB (router 4.2, dialogs 1.9): the budget test needs 12.8 or an eager-only measurement, owner's call.** | the first question and a `<xo-router>` added later cost one extra request; `router.current` is null until loaded; existing dialog tests needed a warm-up call because the first dialog now appears after the module loads |
| (old row 1, kept for the record) | 49% of the 245 KB of JS that loads never runs on the people screen (router.js alone 21 KB) | **not done, needs a decision**: `@xoong/ui` exports `router` as a synchronous singleton (`router.navigate`, `router.current`, `router.guard`) and registers `<xo-router>`; loading it lazily changes the API, or needs a subpath export (`@xoong/ui/router`) that moves `router` out of `@xoong/ui` (breaking), or a facade whose methods wait for the module (changes timing). Potential: about 120 KB raw, a third of the gzip | breaking API |
| 4, 5 | Per-template binding plan, one effect per row, event delegation | JS is 18% of the creation (about 118 ms of 639): the browser's layout (271 ms), style (101 ms) and DOM creation are the rest, and they are the same cost for any stack that draws the same table | **ceiling about 8% of the creation time** (all of the JS removed would be 118 ms; a plan refactor realistically halves it); not started: a large rewrite of `bindNode` for at most 5% | high (the core of the view) |
| 6 | Layout | 271 ms, 42% of the creation | shared with every stack; `table-layout: fixed` would change how columns size, so it is not applied | visible change |

| 4, 5 (tried, reverted) | Binding plan / fewer per-node arrays | tried the cheap parts: no `getAttributeNames()` for an element without attributes, no copy of `childNodes` (take `nextSibling` first) | allocation 6,479 to 6,502 bytes per row, creation 608 to 622 ms: **no gain**, reverted.
